分清真人和机器

每次访问都会标记为真人、爬虫或可疑，并写明原因。统计和报告默认只算真人，刷量、爬虫、链接预览不会把数字撑大。

用 VPN 的真人也不会被误判：机房 IP 只有再带上机器特征才算可疑，浏览器特征完整的仍算真人并标记“经代理”，还能看到有多少真人是翻墙来的。

05 工作方式

三步，从链接到洞察。

01

创建短链

自定义后缀或自动生成。可以先建短链、之后再填推广地址，并设置有效期和参数透传。

02

配置跳转规则

设置默认地址，再按国家 / 地区、设备指定落地页，或按比例做 A/B 测试。同一类规则不会重叠，优先级清楚。

03

投放并分析

为每个渠道生成投放链接，在后台实时查看来源、地区、设备，以及每条规则的命中情况。

06 部署

五分钟，拥有自己的短链服务。

一键部署会自动创建 Worker 和数据库；也可以用命令行手动部署。数据完全保存在你自己的 Cloudflare 账号中。

  • 不需要服务器，不需要维护数据库
  • 表结构自动创建，首次登录引导设置密码
  • 绑定自己的域名，例如 go.example.com

07 常见问题

你可能想知道。

没找到答案？在 GitHub 提问

代码以 MIT 协议开源，可以免费使用、修改和商用。服务运行在你自己的 Cloudflare 账号上：Workers 免费版每天 10 万次请求、D1 免费版 5 GB 存储，绝大多数场景用不完。

使用 Cloudflare 根据访客 IP 给出的国家 / 地区代码，不需要额外的 IP 库，也不会拖慢跳转。香港、澳门、台湾可以单独设置规则。

很多网站和 App 不发送 Referer，只看 Referer 会把大量访问记成“直接访问”。为每个投放渠道使用不同的 src 参数，来源统计会准确得多，后台可以一键批量生成。

可以。访客通常是先搜到你的推广页、再点页面上的短链，这时短链只能看到推广页。在后台“设置 → 来源追踪”开启后，把一行 script 放到推广页上，它会识别 Google、Bing、百度、搜狗、360 等搜索引擎和广告点击，给短链加上 utm_source，原有的 src 不受影响。搜索引擎早已不再传递搜索关键词，所以能知道是哪个搜索引擎，但看不到具体关键词。

可以。每次访问都会被标记为真人、爬虫或可疑：自报身份的爬虫和链接预览（如 Googlebot、微信 / Telegram 预览）算爬虫；没有语言信息、同一 IP 短时间内反复访问，或同时带有多个机器特征（缺少浏览器请求头、HTTP/1.1、iOS 13 之类的旧版本）的，算可疑。来自腾讯云、阿里云、AWS 等机房 IP 的访问，带有任一机器特征就算可疑，浏览器特征完整的则算经代理的真人。后台统计和定时报告默认只算真人，每条访问都能看到判定原因。这是基于网络特征的推断，经过住宅代理运行的脚本仍可能被当作真人；识别结果只用于统计，不影响跳转。

不会。VPN 和代理节点大多架在机房里，但只有“机房 IP + 机器特征”（如缺少浏览器请求头、过旧的系统版本、HTTP/1.1）才会被判为可疑；浏览器特征完整的访问仍算真人，并标记为“经代理”。中文访客出现在非中文地区时也会提示“可能经代理”。后台能看到真人里有多少是经代理来的。住宅代理和手机热点无法识别，会被当作普通访问。

给地区规则打开“打不开时回退到默认地址”。命中规则的访客会先在自己的网络里检测这个地址能否连通，能打开就直接跳过去（通常只多 0.2–1 秒），连不上就改去默认地址；后台会统计每条规则的回退次数。

给默认地址或任意一条跳转规则打开 A/B 分流，加上几个版本并设定比例。按访客 IP 分配，同一位访客总是去同一个版本，反复点击也不会来回跳。后台对比各版本的命中数；开启转化追踪后，跳转会带上 utm_content=ab-a、ab-b……，在 GA4 里就能对比各版本的会话和关键事件。

会。定时任务每小时分批检查已启用短链的所有目标地址，连续两次返回 404、5xx 或超时才算打不开，推送到 Telegram 或邮箱，恢复后再通知一次。对方用 403 或人机验证拦截检查请求时只标记“无法验证”，不算故障。短链列表会标出“目标异常”，详情页可以手动检查。

能。每个短链都有修改记录：默认地址、跳转规则、A/B 比例、启用状态等每次修改都会记下修改前后的内容、时间和操作的设备，保留一年。点“撤销”即可改回去；如果之后又被改过，会提示你手动处理，避免把新的修改覆盖掉。

支持。后台默认跟随浏览器语言，也可以在“设置 → 界面语言”或登录页切换中文 / English；这个首页右上角也能切换。统计报告、推送消息和 AI 分析报告目前仍是中文。

不是必须的。在 Bing Webmaster Tools 里添加站点（已在 Search Console 验证的可以一键导入），生成一个 API Key 填到后台即可，Bing 的点击、展示、搜索词和收录情况就会和 Google 的数据合并显示。值得接的原因是 ChatGPT 搜索、Copilot、DuckDuckGo 都用 Bing 的索引：没被 Bing 收录的页面，在这些地方也搜不到。没收录的网址可以在后台直接提交给 Bing。

GA4 只申请只读权限（analytics.readonly）；Search Console 申请 webmasters 权限，除了读取数据，只用来在你点“提交”时提交站点地图，不会改动其他设置。用的是你自己在 Google Cloud 创建的 OAuth 客户端，刷新令牌加密后保存在你自己的 D1 数据库里，可以随时断开；可以连接多个 Google 账号，所有站点按域名合并显示。

链接是只读的，只包含你选中的站点，用 128 位随机地址，默认 7 天后失效，默认隐藏账号邮箱和媒体资源 ID；每个链接每小时最多打开 60 次，不会被搜索引擎收录。后台能看到每次打开的时间、来自哪个 AI 工具和 IP，可以随时撤销。有些 AI 不能打开链接，也可以下载 Markdown 文件上传给它。

填上一个只读的 Cloudflare API 令牌后，后台能看到整个账户的 D1 读写和 Worker 请求用量，按最近的速度推算到月底（免费版推算到当天结束），预计哪天用完一目了然；在“通知”里开启用量预警，快用完时会推送到 Telegram 或邮箱。统计页面读的是按小时 / 按天的汇总表，本身用量很小。

短链和访问记录都保存在你账号下的 D1 数据库里，可以随时导出 CSV。项目本身不收集、不上报任何数据。后台首次登录必须修改默认密码，密码加盐哈希存储，并可开启 Turnstile 人机验证。
